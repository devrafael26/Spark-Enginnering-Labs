## Spark Engineering Lab 33 - Antes vs Depois

## Categoria

Optimization Case Study

---

## Objetivo

Comparar o estado baseline e o estado otimizado da tabela utilizada no Lab 32, mantendo os mesmos dados e a mesma consulta, para verificar quais diferenças aparecem na execução real.

O objetivo principal deste laboratório não foi buscar apenas uma redução de tempo total, mas observar se a otimização da organização física dos dados produziu evidências concretas no Query Profile, principalmente em:

- arquivos lidos;
- arquivos eliminados por pruning;
- bytes lidos;
- bytes eliminados por pruning;
- tempo associado ao Scan;
- memória;
- tempo total da consulta.

Este laboratório encerra a série Spark Engineering Labs utilizando uma comparação controlada de antes e depois.

---

## Pergunta

Como a organização física dos mesmos 300 milhões de registros influencia a leitura dos dados e a execução da mesma consulta?

# Benchmark

Além do Query Profile, foi executado um benchmark com sete rodadas.

A ordem entre baseline e versão otimizada foi alternada para evitar executar sempre a mesma consulta primeiro.

## Código

```python
from time import perf_counter
import statistics

baseline_table = "workspace.default.lab32_orders_large"
optimized_table = "workspace.default.lab32_orders_large_clustered"

query_baseline = f"""
SELECT *
FROM {baseline_table}
WHERE order_date >= DATE '2026-08-01'
"""

query_optimized = f"""
SELECT *
FROM {optimized_table}
WHERE order_date >= DATE '2026-08-01'
"""


def executar_benchmark(query):
    inicio = perf_counter()

    total = spark.sql(query).count()

    tempo = perf_counter() - inicio

    return total, tempo


baseline_times = []
optimized_times = []

print("=== BENCHMARK LAB 33 ===\n")

for rodada in range(1, 8):

    if rodada % 2 != 0:

        baseline_count, baseline_time = executar_benchmark(query_baseline)
        optimized_count, optimized_time = executar_benchmark(query_optimized)

    else:

        optimized_count, optimized_time = executar_benchmark(query_optimized)
        baseline_count, baseline_time = executar_benchmark(query_baseline)

    baseline_times.append(baseline_time)
    optimized_times.append(optimized_time)

    print(f"RODADA {rodada}")
    print(f"Baseline:  {baseline_time:.3f} s")
    print(f"Otimizada: {optimized_time:.3f} s")
    print(f"Linhas baseline:  {baseline_count:,}")
    print(f"Linhas otimizada: {optimized_count:,}")
    print("-" * 40)


print("\n=== RESUMO ===")

print("\nBASELINE")
print(f"Mínimo:  {min(baseline_times):.3f} s")
print(f"Máximo:  {max(baseline_times):.3f} s")
print(f"Média:   {statistics.mean(baseline_times):.3f} s")
print(f"Mediana: {statistics.median(baseline_times):.3f} s")

print("\nOTIMIZADA")
print(f"Mínimo:  {min(optimized_times):.3f} s")
print(f"Máximo:  {max(optimized_times):.3f} s")
print(f"Média:   {statistics.mean(optimized_times):.3f} s")
print(f"Mediana: {statistics.median(optimized_times):.3f} s")
```

# O que está documentado oficialmente

## Liquid Clustering

A documentação oficial da Databricks descreve Liquid Clustering como uma técnica de organização dos dados baseada em chaves de clustering para melhorar a disposição física dos registros e favorecer o desempenho das consultas.

A documentação informa que consultas que filtram pelas clustering keys podem se beneficiar de data skipping.

Documentação oficial:

https://docs.databricks.com/gcp/en/tables/clustering

---

## OPTIMIZE FULL

A documentação oficial informa que, ao habilitar ou alterar clustering keys, os dados existentes não são necessariamente reorganizados automaticamente.

Para forçar o reclustering dos dados existentes, pode ser utilizado:

```sql
OPTIMIZE <table_name> FULL
```

No Lab 32, essa operação foi utilizada para reorganizar os dados existentes de acordo com:

```text
CLUSTER BY (order_date)
```

Documentação oficial:

https://docs.databricks.com/gcp/en/tables/clustering#force-reclustering

---

## Data Skipping

A documentação oficial da Databricks informa que estatísticas por arquivo são utilizadas para permitir data skipping.

Entre essas estatísticas estão:

```text
minimum values
maximum values
null counts
record counts
```

No momento da consulta, arquivos que não podem satisfazer determinado predicado podem ser ignorados.

Documentação oficial:

https://docs.databricks.com/gcp/en/tables/data-skipping

# Conclusão

O Spark Engineering Lab #33 comparou duas tabelas contendo os mesmos 300 milhões de registros e executou a mesma consulta sobre ambas.

A versão baseline possuía 32 arquivos e não utilizava Liquid Clustering em `order_date`.

A versão otimizada possuía 8 arquivos e havia sido reorganizada no Lab 32 utilizando:

```text
CLUSTER BY (order_date)
+
OPTIMIZE FULL
```

As duas consultas retornaram exatamente:

```text
64.444.438 registros
```

demonstrando equivalência funcional.

A principal diferença apareceu no Query Profile.

O baseline leu:

```text
32 arquivos
28,04 MB
```

sem realizar pruning de arquivos.

A versão otimizada leu:

```text
2 arquivos
3,35 MB
```

e eliminou:

```text
6 arquivos
180,92 MB
```

por pruning.

O tempo associado ao Scan caiu de:

```text
678 ms
```

para:

```text
156 ms
```

uma redução aproximada de 77% nesse operador.

O benchmark de sete rodadas apresentou diferença pequena no tempo total típico da consulta:

```text
Mediana baseline:  0,856 s
Mediana otimizada: 0,833 s
Diferença:         2,76%
```

A média apresentou diferença de 11,40%, mas foi influenciada pela primeira execução do baseline, que registrou 1,619 s e ficou significativamente acima das demais rodadas.

Por isso, o ganho de wall-clock não foi utilizado como evidência principal.

A conclusão central deste Lab é:

> A otimização da organização física dos dados produziu uma melhoria clara e mensurável na eficiência da leitura. O Query Profile mostrou redução substancial de arquivos lidos, bytes lidos e tempo de Scan, embora o ganho no tempo total da consulta tenha sido pequeno neste workload específico e com leitura atendida pelo cache.

Assim, o Lab 33 encerra a série reforçando um dos principais aprendizados construídos ao longo dos laboratórios:
